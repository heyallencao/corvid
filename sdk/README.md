# Corvid SDK

```js
import { connect } from './sdk/index.js';

const client = await connect({ dataDir: process.env.CORVID_DATA_DIR });
try {
  const room = await client.createRoom('Research');
  const page = await room.open('https://example.com');
  const view = await page.snapshot();
  console.log(view);
  // await page.click(view.items.find(item => item.name === '...').ref);
  await room.yieldControl();
} finally {
  await client.disconnect();
}
```

`client.rooms()` and `client.room(id)` find rooms. `client.profiles()` and `client.createProfile(name)` manage browser profiles; `client.createRoom(name, {profileId})` selects one. A room can `open(url)`, list `tabs()`, access `page(tabId)`, and request `yieldControl()` / `resumeControl()`. Room-scoped read-only site commands are available through `siteCommands()`, `proposeSiteCommand({tabId, name, description, steps})`, and `runSiteCommand(commandId, tabId, {trial})`; proposals remain candidates until a user reviews them in Corvid settings and retains them after a successful trial. A page supports `navigate`, `back`, `forward`, `reload`, `snapshot`, `click`, `fill`, `press`, `scroll`, `selectOption`, `select`, `wait`, `screenshot`, `evaluate`, `text` and `close`. `back()` and `forward()` use that managed page's history and leave the current document unchanged when no corresponding history entry exists. `reload()` repeats the current document request. These methods require agent control. Actions accept a snapshot reference or a CSS selector. `evaluate` executes supplied JavaScript and therefore requires agent control.

`page.fill(target, value)` accepts editable text inputs, textareas, and `contenteditable` editing hosts; a locator may identify the host or one of its descendants. The SDK selects content only within the nearest editable host, then uses trusted Backspace and Chromium text input. Input is literal text rather than HTML, and Chromium renders newline paragraph boundaries according to the editor's behavior. Existing formatting at the insertion point may remain.

`page.scroll(deltaX, deltaY, {x, y})` sends one bounded CDP scroll gesture with a mouse input source at the given main-viewport CSS-pixel position; omit both coordinates to use the viewport center. Positive deltas scroll right/down. Each finite delta is limited to -2000 through 2000, and both cannot be zero. Coordinates must be finite and supplied together, and the desktop rejects points outside the viewport. The single Room-serialized operation targets nested scroll containers and background pages without activating their Room. Scrolling can trigger lazy loading or other site behavior; inspect the page afterwards.

Administrators can call `client.createAgentClient(name, roomIds)` to issue a scoped credential once, `client.agentClients()` to review grants, and `client.revokeAgentClient(id)` to revoke one immediately. Connect a scoped client with `connect({token})`; the SDK reads only the current local control endpoint from `control.json` and uses the explicitly supplied scoped token, never the administrator token. An explicit `baseUrl` must be paired with `token` and point to a `127.0.0.1` HTTP endpoint. Scoped clients can enumerate and operate only their granted Rooms and cannot enumerate Profiles without a granted Room, and cannot access history, bookmark, download, or window endpoints. Credentials are stored as SHA-256 hashes with owner-only file permissions. The administrator credential remains available to local processes that can read the Corvid data directory, so scoped clients do not provide OS-level isolation against a malicious process running as the same user.

The built-in Corvid Agent follows the same server-side identity and Room checks. Corvid issues a separate in-memory credential for each task turn, restricted to that task's one Room, rotates it for a continuation, and revokes it on completion, failure, stop, or user takeover. The built-in credential is not written to the external client store, task record, or conversation transcript. Users do not need to create or configure a credential for the built-in Agent. This does not isolate against a malicious process running as the same OS user that can read the administrator's `control.json` or control the Corvid main process.

## Browser MCP scoped access

Create a named client from Corvid **设置 → 管理 Agent 访问**, select its allowed spaces, then copy the one-time key into the MCP host's local environment configuration. Configure the server with `CORVID_AGENT_TOKEN` (and `CORVID_DATA_DIR` when Corvid uses a non-default data directory):

```json
{
  "mcpServers": {
    "corvid": {
      "command": "corvid-mcp",
      "env": {
        "CORVID_AGENT_TOKEN": "<paste the one-time key>",
        "CORVID_DATA_DIR": "<optional Corvid data directory>"
      }
    }
  }
}
```

The MCP server refuses to start tool requests without `CORVID_AGENT_TOKEN`; it never falls back to the administrator credential. Keep the host configuration local and private. Revoke a client in Corvid settings to invalidate its key immediately. When the active browser view is the new-tab start surface, page actions for a background Room are still limited; see [Issue #98](https://github.com/heyallencao/corvid/issues/98).

The page tools include `page_back`, `page_forward`, and `page_reload`. Each requires an explicit `roomId` and `tabId`, and operates only on a managed page while the Agent owns that Room without a pending user handoff or unresolved execution risk. Back/forward with no matching history entry are successful no-ops; reload sends the current document request again. A tool result acknowledges the requested browser action, not that a site-side operation succeeded; inspect `page_info` or `page_snapshot` afterwards.

The site command tools are `site_propose`, `site_try`, `site_search`, and `site_run`. A proposal stores a candidate tied to its Room and the exact HTTP(S) origin of the selected managed Page. Its versioned declarative steps currently allow only page metadata (`info`) and bounded semantic snapshots (`snapshot`, `page` or `viewport`); scripts, locators, navigation and page actions are rejected. `site_try` runs a candidate and records a successful trial but does not retain it. The user reviews its name, origin, description and steps in **设置 → Agent 与连接**, then explicitly retains or deletes it. `site_search` and `site_run` expose retained commands only. Every run requires an explicit Room and Page and rechecks Agent control, handoff state, execution risk, managed Page membership and exact origin. Commands do not carry authorization to another Room/Profile. The app stores them in a new owner-only `site-commands.json` file; deleting a Room does not grant access to its commands, which remain scoped to that stable Room ID until the user deletes them in settings.

`page_wait_for_url` waits for an exact URL string, `page_wait_for_load` waits for `domcontentloaded` or `load`, and `page_wait_for_selector` waits for one locator to become `attached`, `detached`, `visible`, or `hidden`; they return current page info. Selector waits accept only the shared locator forms and do not run arbitrary callbacks or page scripts. Each MCP wait defaults to 10 seconds and is limited to 60 seconds; `networkidle` is not supported. Every polling action rechecks Room control, so waits stop when the user takes control or execution risk requires review.

`page_hover` moves over one locator and can reveal site menus or tooltips. `page_select_option` sets select-control values by value/label string or value/label/index criteria, supports multiple values and clearing, and returns selected values; selection updates option state and emits untrusted `input`/`change` events rather than operating the native picker. Additional SDK options are not exposed through MCP. Both are site actions and can change page state.

`page_scroll` accepts `deltaX`, `deltaY`, and optional paired `x`/`y` coordinates in main-viewport CSS pixels. Each delta is bounded to -2000..2000 and at least one must be nonzero. Omitted coordinates use the viewport center. It sends a mouse-source scroll gesture through CDP, which can target nested scrollers and background pages without activating the Room. It is a page action that may change site state or load content; the MCP tool requires explicit Room/Tab scope and Agent control.

`page_screenshot` returns the selected managed page viewport as an MCP `image/png` content item. It uses the same explicit Room/Tab and Agent-control checks as page reads, does not activate a background Room or save an image to disk, and rejects images larger than 8 MiB with `CORVID_OUTPUT_TOO_LARGE`. The MCP host must support image content to display or pass the result to a vision model; full-page capture is not exposed through MCP.

`page_new` creates a blank managed page in the explicitly selected Agent-owned Room and returns its Page info; use `page_navigate` separately to load an HTTP(S) URL. `page_close` only closes a managed page created by the Agent. User-created and unknown-origin pages are refused, and a site `beforeunload` prompt may require user confirmation.

`client.openRoom(nameOrId, {profileId})` creates or resumes a uniquely named agent-owned room; a user-owned, ambiguous, manually controlled, or risk-blocked room is not silently taken over. New agent rooms have a `p1` page. `room.page('p1')` creates a lazy handle, `room.pages()` lists labeled pages, and `room.newPage()` allocates the next label. Labels and page identity survive application restart and used labels are not reused. `roomId` and `goto()` are aliases for `id` and `navigate()`. Legacy pages with unknown origin remain unlabeled; agent requests cannot close user-created or unknown-origin tabs or a room containing them.

`await room.waitForControl({interval, timeout})` polls until the room is agent-controlled with no pending user resumeControl or unresolved execution risk; it never requests or takes control. Defaults are 20,000 ms and 600,000 ms. Both options must be positive milliseconds no greater than 2,147,483,647. A closed room or an unavailable desktop connection fails the wait. The observed state may change again immediately, so each subsequent action still checks control independently.

`page.url()` and `page.title()` read the desktop's current tab state. `page.waitForURL(matcher, {timeout})` polls that state for an exact string, URL glob (`*`, `**`, and `{a,b}`), RegExp, or synchronous function receiving a URL object. The default timeout is 10 seconds. It does not block another page operation; it stops if control is lost or the page is released or closed. Polling can miss a URL that exists only between observations, and a match does not imply that the document has finished loading. Popup waits currently rely on polling the desktop state and do not interrupt the triggering action.

`page.waitForLoadState('domcontentloaded' | 'load', {timeout})` waits for the corresponding top-level document event; `load` is the default. The state belongs to the currently committed document, so a call made before a new navigation commits can observe the previous document. The method checks control on every poll. `networkidle` and `idleMs` are not yet supported, and DOM readiness does not imply other SDK page actions can execute before all resources finish loading.

`page.waitForSelector(target, {state, timeout})` waits for `attached`, `detached`, `visible` (the default), or `hidden`, polling with a default 10-second timeout. Each probe checks ownership, and multiple matches fail rather than choosing one. Visibility uses element and containing frame geometry and computed display/visibility; it does not check occlusion. The existing locator and frame limitations apply. A missing or inaccessible explicitly selected frame is an error, not proof that its target is hidden or detached; stale snapshot references also remain errors.

`page.waitForFunction(fnOrExpression, argument, {timeout, polling})` evaluates a function or expression until its result is truthy. Callbacks may be asynchronous and receive one JSON-serializable argument; pass `undefined` before options when omitting that argument. Defaults are 10 seconds and 100 ms. The callback runs in the page and may have side effects. Each probe uses the existing evaluation safety deadline: if a callback does not settle, the room enters an unresolved execution-risk state and the callback may continue; the minimum per-probe deadline is 100 ms. A normal condition timeout after settled false results does not indicate unresolved execution. Navigation-context retries and popup hints are not implemented.

For a popup, start `const pending = page.waitForEvent('popup')` before `await page.click(...)`, then await `pending`. Actions on the same Page handle wait for the observation baseline to be established. The returned ready popup is adopted with a label, but retains unknown origin and cannot be closed by the agent. Only popups attributed to that opener after the baseline are matched. A bounded in-memory event history preserves the first popup even if it closes between polls; a closed popup and an expired history are reported as errors. A popup that never finishes initializing can time out. History and opener relationships are not restored across app restart.

Use the same pattern with `page.waitForEvent('download', {timeout})` to capture a download initiated by that page, then call `download.url()`, `suggestedFilename()`, `page()`, `failure()`, `path()`, `saveAs(absolutePath)`, `cancel()`, or `delete()`. The wait timeout is 100–60,000 ms. `path()` and `failure()` wait for completion; `saveAs` creates parent directories and may replace the specified destination. Cancel a running download and wait for it to settle before `delete()`. Agent downloads use application-owned temporary files, are not included in the normal downloads list, and are removed on explicit deletion or normal application exit, not on SDK disconnect. Save needed files before exit. Calls remain bound to the source page and agent control; a started transfer can continue during yieldControl, but its handle cannot be used until control returns. Cross-frame attribution, abnormal process exit, Windows cleanup and other download protocols remain unverified.

`page.fetch(url, options)` executes `window.fetch` in the page, using its browser session, relative URL resolution, cookies and CORS rules. It returns status, headers and a UTF-8 `body`; `{saveAs: '/absolute/path'}` saves the original bytes and returns `savedPath` instead of `body`, replacing an existing destination. Standard string request options, string headers and a string body are accepted. Responses are limited to 8 MiB; the timeout must be an integer from 100 to 59,000 ms. Timeout aborts the browser request where possible, but does not undo server-side effects. If evaluation itself fails to settle, the existing execution-risk state applies. Request body size is also bounded by the local control transport; streaming results and large files are not supported by this method.

`page.screenshot()` returns a PNG Buffer of the viewport. `{fullPage: true}` captures the page content, and `{clip: {x, y, width, height}}` captures a rectangle in CSS pixels; these two options cannot be combined. Full-page and clipped images are scaled to CSS pixels and limited to 16,384 pixels per side and 32 million pixels. `{path: '/absolute/path/image.png'}` creates missing parent directories, writes or replaces that file, and returns the path. Without `path`, the return value is a PNG Buffer. Explicit `scale` and `raw` options are not implemented; the default viewport capture may use device pixels.

`room.tabs()` lists managed and unmanaged tabs, including whether initialization is complete. Use `room.adopt(tab, {as?})` to assign an unused label to a ready unmanaged tab before agent operations; adoption does not change its origin. `room.release(label)` removes management of a user or unknown-origin page without closing it. Agent-created pages must be closed rather than released. `room.finish({keep: []})`, `room.finish({keep: ['p2']})`, or `room.finish({keep: 'all'})` validates the full keep list, closes only unkept agent-created managed pages, and gives retained tabs to the user with all labels removed. An empty room is closed. A finished room cannot be resumed through `openRoom()` or `resumeControl()`; `client.claimRoom(id)` requests the user's approval to claim it. `room.userPage()` returns a handle to the active tab in that Room handle's current snapshot, which must be adopted if unmanaged. These behaviors are covered by local end-to-end tests; the API contract is still being completed (see `docs/execution/feature-board.md`).

Closing a page or finishing a room honors `beforeunload`. The browser asks the user and transfers an agent-controlled room to them. If the user stays, the page remains open and its debugger is reattached; a multi-page close can already have closed earlier pages, and the error reports partial completion. A `finish` interrupted by user control does not return a success receipt, even when the user permits the last page to close. Handle the current room state before continuing.

All local SDK and CLI clients currently share one desktop credential and an agent ownership class. The application does not yet identify individual agents, so any authenticated local client can resume another agent-owned room by name or ID. Choose distinct task names; do not treat this as per-agent access isolation.

Run `node cli/corvid.mjs run < task.js` while the desktop is running. The script receives `openRoom`, `listRooms`, `resumeRoom`, `claimRoom` and `client`, and supports top-level `await` and dynamic `import()`. Claiming prompts the user in the desktop; a denied request leaves the room user-owned. The input is executed as an async function, not an ESM module: static `import` and `export` declarations are unsupported. It runs with the local user's Node.js permissions. `node cli/corvid.mjs help` prints a concise usage guide; installation into other agents is not automatic.

`page.snapshot(options)` returns `{ url, title, scope, items, truncated, total, limitations, inaccessibleFrames }`. Each item is `{ ref, role, name, frame }` where `ref` is a stable short reference such as `@12` and `frame` is the containing same-origin frame label (or `null` for the top document). References identify actual nodes: a main-frame navigation invalidates them, detached or replaced nodes are rejected, and the same node keeps its reference across snapshots until the document is replaced. Refs are accepted by actions as `@12`, `ref=12`, or the raw string printed by the snapshot.

`options.scope` controls collection:

- `page` (default): all visible interactive elements in the committed document, including nested same-origin iframes and open shadow roots (up to 200 items; `truncated` and `total` report the cut).
- `viewport`: only elements whose absolute rect intersects the current viewport, still including same-origin frames.
- `subtree`: requires `options.root` (a `@ref` or selector); collects inside that element, its open shadow root, or the iframe document it points at.

Collection walks same-origin iframes recursively, so multi-level same-origin nesting is included; cross-origin frame contents and closed shadow roots are excluded and counted in `inaccessibleFrames`. Names and roles approximate the accessibility tree rather than reproducing it.

The desktop service checks ownership for automation operations and serializes page actions with yieldControl and resumeControl. Dialog observation and responses bypass that queue so a pending action can be unblocked; they still check ownership. A bounded wait can delay yieldControl by up to 10 seconds. The control file contains a bearer token; protect it as a credential. Desktop must be running, and the SDK must use the same `CORVID_DATA_DIR` as the desktop.

The user can take control from the desktop UI. Once requested, new agent actions are rejected while an already running action finishes. A user-initiated takeover remains locked across restart; the user must choose “交还 Agent” before the agent can resume. If the application exits before the takeover completes, the next launch retains user control and marks the previous operation outcome unknown for user review.

`click`, `fill`, and `press` use browser input commands through a page-owned Electron debugger, also used to observe JavaScript dialogs; no CDP endpoint is exposed. Opening another DevTools session can detach it; dialog state is then unknown and input may be unavailable until it reattaches. `fill` supports text, search, URL, telephone, and password inputs, textareas, and contenteditable editing hosts; `press` supports ASCII letters and digits, Enter, Tab, Escape, Backspace, Delete, Home, End, arrow keys, and space; modifiers are Control/Ctrl, Alt, Meta/Command and Shift, for example `Control+a`. On macOS, `Meta+a` and Meta+Left/Right (including Shift selection variants) dispatch the matching Chromium editing commands for focused text controls and contenteditable hosts. Other platform-specific editing bindings and IME behavior are not verified; keys outside the documented set are unsupported. `wait` currently waits only for a target to exist, for at most 10 seconds; other Playwright wait states and options are not implemented. References from the snapshot can target same-origin iframe and open shadow elements; By default CSS, role, text, and href locators search the main document and open shadow roots; use the object locator’s `frame` field to select a unique top-level same-origin iframe. XPath searches the selected document and does not pierce shadow roots. Cross-origin frames and closed shadow roots are unsupported. Frame navigation invalidates references into the old document. `evaluate` accepts an expression string or a function with a JSON-serializable argument and returns a JSON-serializable value.

`evaluate(fn, arg, { timeoutMs })` defaults to 10 seconds and accepts 100–60000 ms. A timeout throws an error with `status: 'timed_out'`, `operationId`, `executionStopped: false`, and `mayHaveLateEffects: true`. The room blocks further agent actions until a user reviews the warning in the desktop UI; yieldControl remains available. A timeout does not cancel page code or undo requests, timers, or other effects. After a restart, the saved state remains unknown until reviewed. Synchronous renderer hangs and all possible late effects are not covered by the current tests.

Run the reusable input regression against a separately started desktop with an isolated data directory: `CORVID_DATA_DIR=/path/to/test-profile node sdk/e2e.js`. It checks that the page receives trusted click, input and keydown events, along with focus and values. A trusted event does not establish compatibility with every site or anti-automation system.

Locator inputs include raw CSS, `loc=css:button`, `css=button`, `xpath=//button`, `text=Submit`, `text="Submit"`, `loc=href:/path`, and `loc=role:button[name="Submit"]`. A small Playwright-compatible subset is accepted: terminal `:has-text("...")` and `:text-is("...")` on a CSS selector, and `>> nth=N` (`N` is `-1` or non-negative) after a CSS, text, href or role locator. Unquoted text is case-insensitive substring matching; quoted text is exact. `loc=role:button[name*="sub"]` is a case-insensitive name substring. All locators require exactly one match. For explicit scope use `{by: 'role', value: 'button', name: 'Submit', frame: '#frame'}`; `by` also accepts `css`, `xpath`, `text`, or `href`, with optional `exact: false` for text/name substring matching. Role and name are simple DOM approximations, not a complete accessibility computation. Only top-level same-origin frame scoping is supported; it does not automatically search frames. Shorthand refs such as `@N`, `:has-text`, `:text-is`, and `>> nth=` are not supported.

A Page exposes `dialog()`, `acceptDialog(promptText?)`, and `dismissDialog()` for page-authored alert, confirm, and prompt dialogs. These can be called from another SDK connection while the action that triggered the dialog is pending. Electron does not implement `window.prompt`; the desktop supplies a synchronous preload bridge for the top-level document. The desktop prompts the user for `beforeunload` during navigation and page closure. Cross-frame prompts, debugger detachment while a dialog is open, and dialog behavior across application restart have not been verified. The desktop UI also exposes a dialog response control.

`page.setInputFiles(target, paths)` selects existing local regular files by absolute path, or clears a file input with an empty array. It supports a single path or an array, checks the input's `multiple` setting, and uses the existing locator or snapshot reference. Clearing uses the DOM value setter and dispatches untrusted `input` and `change` events because the tested Chromium CDP call did not clear the selection with an empty array. Same-origin iframe and open shadow inputs are covered by local tests. A change handler can open a dialog: observe and answer it through `dialog()` and `acceptDialog()` / `dismissDialog()` while the upload call is pending. Directory uploads and cross-origin frames are not yet supported.

For an input created by a click, call `const waiting = page.waitForFileChooser({timeout: 10000})`, then `await page.click(target)` and `const chooser = await waiting`. Use `await chooser.setFiles('/absolute/path')` or `await chooser.cancel()`. The chooser is bound to the original node and expires after the requested timeout (100–60000 ms); yieldControl cancels interception. Only file-input-backed choosers and nonempty file selections are supported. To clear an existing input, use `setInputFiles(target, [])`. The tests cover a top-level input and a change-handler dialog, but not cross-origin frames, directory choosers, debugger detachment, or native picker UI.

Permission requests from an agent-owned main document transfer the room to the user before showing the permission decision. The agent must request resumeControl after the user decides. Notification and geolocation grants are scoped to the origin and Profile for the current app run and can be reviewed or revoked through the desktop's “站点权限” button; grants are not persisted across restart. Other permissions remain request-specific. Electron's boolean permission-check API currently causes a site with no stored grant to observe `denied`, rather than distinguishing a prior denial from an undecided state. Device choosers and operating-system permission behavior remain incomplete.

`page.selectOption(target, choice)` accepts a value-or-label string, `{value, label, index}` criteria, an array of choices, or `null` / `[]` to clear. It returns selected values; `page.select` is an alias. Additional options, including a timeout, are not supported. The select itself must be visible and enabled; disabled options may be selected programmatically. This updates DOM option state and emits untrusted `input` and `change` events, rather than operating the native picker. Same-origin frame and open shadow controls are covered by local tests.

`page.hover(target)` moves the pointer to an element, and `page.dragAndDrop(source, target)` drags between element centers. Both drag endpoints must fit in the viewport at the same time; position, force, label and timeout options are not supported. `page.mouse.move(x, y)`, `.click(x, y, {button})`, `.down({button})`, `.up({button})`, and `.wheel(deltaX, deltaY)` use main-viewport CSS pixels and support left, right and middle buttons. Wheel input is dispatched at the last pointer position; dispatch completion does not prove scrolling has finished. Held buttons are released before a normal yieldControl or tab closure. Tests cover a local HTML drag with transferred text, pointer dragging and wheel events, but do not establish compatibility with all sites, cross-origin frames or OS drag targets.

## Page control, keyboard and raw protocol

`page.reload()` reloads the current page (navigation is asynchronous; wait with `waitForLoadState` or `waitForURL`). `page.focus(target)` focuses a single resolved element and fails when focus cannot be acquired. `page.dblclick(target)` dispatches a trusted double-click sequence. `page.waitForTimeout(ms)` delays without observing the page; prefer a condition wait when one exists.

`page.keyboard` supports `down(key)`, `up(key)`, `press(key)`, `type(text)`, `insertText(text)` and `paste(textOrOptions)`. Keys use the same names as `press()` (`Enter`, `Tab`, `Escape`, `Backspace`, `Delete`, `Home`, `End`, arrow keys, `space`, letters, digits) and `+`-joined modifiers (`Control+a`, `Shift+b`). `down`/`up` maintain modifier state between calls. Modifier chords use the same platform editing-command mapping as `press()`; on macOS this currently covers Meta+A and Meta+Left/Right with optional Shift. `type` and `insertText` use browser text insertion; `paste` writes the system clipboard, triggers a native paste and then makes a best-effort attempt to restore the previous clipboard content.

`page.info()` returns `{ label, targetId, roomId, openedBy, url, title, ready, domReady, loadComplete, dialog }`. `targetId` is the stable tab identity used by the desktop for the lifetime of the page and is not a raw CDP target id.

`page.events()` returns and advances a buffered popup event list. The first call establishes the baseline and returns `[]`; later calls return events observed since the previous call or the baseline, each shaped as `{ sequence, tabId, status: 'initializing' | 'ready' | 'closed', label?, openedBy? }`. The history is in memory only and is not restored across application restart.

Actions resolve with an immediate observation receipt: `{ ok: true, receipt: { popups: [...], dialog: null | { type, message, defaultPrompt? } } }`. A receipt describes what was observed right after the action dispatch; it does not verify the resulting application state. `page.cdp(method, params)` is the raw Chromium DevTools Protocol escape hatch for the addressed page; it returns the CDP response object. Raw CDP can invalidate snapshot references, and no room-level CDP is exposed.

## Errors

Operational failures raise `CorvidError` with a stable `code`:

| Code | Meaning |
| --- | --- |
| `CORVID_NOT_FOUND` | Room, page, tab, profile, download or route does not exist |
| `CORVID_CONTROL_LOST` | The room is under user control, a takeover is pending, the room has an unresolved execution risk, or the tab is unmanaged |
| `CORVID_EXECUTION_RISK` | Page code timed out and the room is blocked until the user reviews it |
| `CORVID_STALE_REFERENCE` | Snapshot reference, page label or room handle no longer applies |
| `CORVID_TIMEOUT` | A bounded wait or chooser expired |
| `CORVID_UNSUPPORTED` | The requested capability is not implemented |
| `CORVID_UNAUTHORIZED` | The control service rejected the credential |
| `CORVID_FORBIDDEN` | The credential is valid but lacks access to the requested resource |
| `CORVID_DESKTOP_ERROR` | Desktop error without a more specific classification |

Argument shape problems keep raising `TypeError` or `RangeError`; only operational failures carry a `CORVID_*` code. Desktop error classification is message-based, so new desktop errors must add a mapping and a regression assertion.
