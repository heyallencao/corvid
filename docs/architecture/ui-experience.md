# Corvid 统一桌面体验设计

状态：active · v0.1
对应执行板：[D21 统一浏览器与 Agent 桌面体验](../execution/feature-board.md)；新标签起始页由 [D22](../execution/feature-board.md) 跟踪。

## 产品方向

Corvid 是可作为日常浏览器使用的完整桌面产品。产品主线按两层组合：以 EGO 的用户日常浏览器与共享 Spaces 为主产品模式，让用户继续使用浏览器时，Agent 在隔离 Space 中并行工作；吸收 Kaze 的内置 Agent 工作台、任务分组/状态/接管，以及 BrowserMCP 外部浏览器操作能力。Corvid 要把这些放进统一的 Profile、Room、Page 和授权合同，建立自己的品牌、视觉语言和交互，不复制参考产品的界面实现。完整参照证据与限制见[双浏览器参照分析](../research/browser-reference-analysis.md)。

当前内置 Agent 集成 Pi SDK 作为可替换的执行运行时。PI 是内部实现选择，不是产品名称、功能名称或用户需要理解的概念。产品始终称为 Corvid Agent；对话、任务、工作区、模型连接、页面来源、授权、错误与恢复均使用 Corvid 定义的产品语义。用户界面、帮助文案、通知和可导出的产品记录不得要求用户认识或操作底层运行库；Provider 与模型名称可以按配置需要展示。

Corvid 持有任务 ID、对话与消息、模型偏好、Profile/Room/Page 绑定、授权边界、控制权和状态呈现。适配器专属的会话检查点属于内部实现元数据，必须封装为可迁移数据；更换或升级执行引擎时，由 Corvid 负责兼容迁移、重新授权或清楚说明恢复限制，用户继续从 Corvid 对话中工作。不得把运行库命名或专属会话格式提升为公开产品合同。

Provider 凭据也由 Corvid 管理：`agent-credentials.json` schemaVersion 2 只保存 Provider 类型和由 Electron 异步 `safeStorage` 生成的密文，当前 Agent 适配器在调用模型时解密使用。schemaVersion 1 与运行时自有凭据文件仅作为一次性迁移来源，旧明文只在新密文写入并解密校验后清理。恢复残留迁移备份时，当前密文验证遇到任何系统安全存储 API 错误（包括不可用、Linux provider 未验证或解密返回值不符合合同）都必须保留当前 schemaVersion 2 文件与 `.migration-backup` 原字节；验证成功但删除旧备份失败时也保留两份文件并显示可本地化提示；遇到未知或更新的 schemaVersion 时保留当前文件和备份并拒绝降级；JSON 语法损坏可回退备份，凭据文件读取 I/O 错误则保留双方并返回本地化错误，不得按文件不存在处理。macOS Keychain、Windows DPAPI 和 Linux 系统密码管理器提供平台密钥保护；Linux 依据异步密文标记拒绝固定口令 POSIX 回退与未审查标记。当前 Electron 45.2.1 / Chromium 156 的 `v11`（Secret Service）和 `v12`（Portal）被接受；此标记是上游内部格式，升级 Electron 时需重新核实。安全存储不可用时保留已有数据；isAsyncEncryptionAvailable()、加密和解密调用均有 15 秒上限，超时返回 secure-storage-timeout；中英文提示仅说明系统安全存储未及时响应、现有凭据已保留并可稍后重试，不再将超时直接归因为钥匙串锁定。其他明确的安全存储不可用错误仍给出相应的密码管理器恢复提示。模型目录加载状态会在 IPC 请求前显示，避免等待期间工作区空白。该超时仅结束 Corvid 等待，不会取消操作系统已经接收的原生调用；真实签名包的安全存储响应仍需单独验收。0600/0700 文件权限继续作为纵深保护；同一 OS 用户下的其他进程仍可能调用当前应用的解密能力。打包签名、钥匙串提示与 Windows/Linux 运行态尚待验证。

Corvid 首个面向用户版本必须完整支持简体中文（`zh-CN`）与英文（`en`），并从第一步建立可增加其他 locale 的本地化资源和格式化边界。此合同覆盖浏览器 chrome、Agent 工作区、设置、菜单、帮助、错误/状态/空态与可访问名称；不翻译网站自身提供的网页主体。新界面文案不得散落在业务逻辑中，日期、数字、复数和较长译文造成的布局变化均需纳入设计与验收。整体跟踪见 [Issue #130](https://github.com/heyallencao/corvid/issues/130) 和执行板 D24。

## 当前基线

- 当前源码与本轮隔离窗口一致：宽窗左侧已无常驻侧栏；空间导航收敛为窗口下缘的悬浮空间 dock（浏览身份、空间磁贴、空间选项与新建空间），书签/历史/下载/设置经工具栏「资料与设置」菜单进入；主区域从标签栏、导航工具栏进入网页画布，dock 下沉时只留一条贴边唤出带。默认空白 `about:blank` 截图未显示网站内容，也没有打开 Agent 工作区或资料库面板。
- `desktop/styles.css` 的空间 dock 使用 `--dock-glass`/`--dock-line`/`--dock-shadow` 玻璃 token，macOS 窗口启用原生 `vibrancy:'under-window'`（不启用 `transparent`），主进程按 `dockStripHeight` 为网页画布让出下缘条带。Agent/资料库面板按需使用右侧工作区，不应把其关闭状态误记为缺少该入口。
- 首次启动时出现 Chrome 资料导入提示；本轮在全新 `CORVID_DATA_DIR` 中选择“稍后”后进入空白页，没有读取或导入用户浏览器资料。该截面只验证了默认壳层级，没有覆盖导入流程、真实网页、多标签拥挤或窄窗。
- 过往 EGO/Kaze 窗口记录只适用于各自证据所列版本、窗口和时间；因浏览器窗口可能含网页主体，本项目当前比较遵守隔离/脱敏边界。没有安全可读的当前运行态证据时，竞品运行态应明确标为未知，而不从旧截图或包内字符串推断。
- 参照边界：EGO 的公开 `ego-lite` 仓库是 Agent harness/技能，不是完整浏览器运行时；Kaze 的开源仓库主要提供公开产品说明、网站与技能，安装版 Electron 包包含实际运行时代码。对 EGO 的闭源浏览器本体不推断未观察到的实现；对 Kaze 的 REA 静态图谱不推断运行时可达性或授权效果。

## 设计原则

1. **EGO 式日常浏览为主，Kaze 式 Agent 协作为内建能力。** 地址栏、标签、网页保持主画布；Agent 通过隔离 Space 并行工作，空间 dock 和任务空间不得夺走用户正在看的页面或隐藏当前控制权。
2. **空间是持续导航。** 延续 EGO 共享浏览器中的隔离 Space 思路，并结合 Kaze 可见的 Space/任务组织；界面统一把 Room 呈现为“空间”、把 Profile 呈现为“浏览身份”，避免用户同时学习多套内部术语；用户空间与 Agent 空间都能被找到，dock 磁贴显示当前选择、站点 favicon 与运行/等待/用户接管等事实状态。空间 dock 在任务准备/运行、等待用户处理、完成待查看时保持唤出并显示与任务摘要同步的状态标记；标记不改变任务存储状态，也不播报独立的重复 live region。
3. **关闭最后一个用户标签仍可继续浏览。** 用户关闭空间中的最后一个标签后保留原空间、浏览身份和窗口，并在原空间打开 Corvid 起始页；用户取消 `beforeunload` 时保留原页面。Agent/API 的关闭生命周期遵守 Agent 契约，不自动补建用户起始页。
4. **Agent 是 Corvid 工作区，不是运行库名称。** 用户可以看到页面来源、托管授权范围（把空间交给 Agent 即授权其读取该空间内已绑定页面的上下文）、对话、运行状态、待处理动作和结果；引擎名称和会话格式仅留在实现与受限诊断中，运行时可以独立替换。
5. **日常能力是一等入口。** 历史、书签、下载、设置在桌面信息架构里稳定可达；站点权限和站点数据属于当前页面的站点工具。
6. **安静、精确、亲和。** 使用低对比中性色、单一品牌强调色、统一间距与圆角、语义图标和清晰层级。状态依靠文案/形状/颜色共同表达，避免依赖 emoji 或颜色单独表达。
7. **浏览器 chrome 图标与连接状态使用可控的 SVG 语义。** 操作图标沿用单一 currentColor 笔画体系，16px/20px 两档尺寸；地址栏按当前已提交页面分别显示加密、未加密、本地或无法确认状态，并提供双语可访问名称。加密只描述连接传输状态，不替网站身份或内容背书；失败导航不能被显示为已加密。
8. **桌面尺寸自适应。** 空间导航由窗口下缘的悬浮空间 dock 承载，不再随宽度切换侧栏档位；Corvid Agent 并排工作区与网页画布在窄窗同步收窄，dock 下沉时只保留贴边唤出带且不劫持页面点击。当前 Chromium `WebContentsView` 位于 shell HTML 之上，不能可靠地用 HTML 面板覆盖网页，因此保持并排布局；桌面窗口基准下限为 704×420 CSS px，显示器工作区较小时按可用边界收缩；CSS 紧凑工具栏断点设为 720px，确保最小窗口可触发。恢复旧窗口状态时也将小于下限的尺寸归一到相同边界。
9. **可访问且可预期。** 控件有可访问名称和清晰 focus-visible，快捷键/触控板可达，减少动态效果设置下仍保留状态转换。
10. **一个空间只运行一项 Agent 任务。** 同一 Room 中同时只能有一项 `preparing` 或 `running` 任务，避免多个会话交错操作同一页面；发送请求期间按钮立即显示处理中并禁用，失败后恢复重试。并行任务通过不同 Room 启动，Room 之间保持独立。
11. **字体尊重操作系统并覆盖中文阅读。** 浏览器壳和 Agent 工作区使用系统 UI sans-serif 与平台 CJK fallback，不依赖用户额外安装 Inter；`zh-CN` 下小型可见 UI 文本至少 12px，英文可保留 10/11px 紧凑层级。浏览数据标题直接表达当前列表，不加与页面内容无关的品牌眉题。
12. **交互状态彼此可辨。** hover 反馈不能覆盖当前选中状态；可按下按钮提供轻微触点反馈；主题化滚动条和文字选区沿用 Corvid 色板；状态过渡统一使用短时长 token，并遵守 `prefers-reduced-motion`。标签栏与扩展工具栏等专门隐藏的滚动条保持原行为。
13. **空间与导航共享选中语义。** 当前空间磁贴与资料库菜单等导航入口使用同一组强调色语言：磁贴选中态使用 accent 描边光环与强调文字，菜单/列表选中项使用强调底色、文字色和内侧指示线；空间身份圆点继续保留为身份/归属线索。主题切换和 hover 不应让已选状态变成两套视觉语言。

## 样式 token 合同

`desktop/styles.css` 是桌面壳层的共享样式 token 边界。圆角采用 4px 步进的 `--radius-xs`（4px）、`--radius-sm`（8px）、`--radius-md`（12px）、`--radius-lg`（16px）和 `--radius-xl`（20px），另以 `--radius-circle` 表达圆形指示器；上下两角圆弧等组合形状可由这些 token 与 0 组合。浮层投影以 `--elevation-card`、`--elevation-raised`、`--elevation-popover`、`--elevation-panel`、`--elevation-menu` 和 `--elevation-dialog` 描述语义层级，投影颜色继续引用浅/深主题下既有的 shadow 色值。焦点 halo 和选中指示等零偏移/内阴影是交互状态，不属于浮层 elevation。Issue #210 本轮只收敛圆角与投影结构；色板、近似灰、状态色和对比度债务继续跟踪，完整状态见[执行任务板 D26](../execution/feature-board.md)。

## 目标信息架构

- **左侧导航：** Corvid 品牌；Profile 切换；Spaces/Rooms 列表与新建；Agent 区（Corvid Agent 对话入口与 Agent Room 列表）；底部书签、历史、下载、设置。
- **浏览器 chrome：** 标签行和新建标签；后退、前进、刷新；地址/搜索输入；收藏与当前站点工具。
- **原生应用菜单：** macOS 使用 Corvid 品牌应用菜单与 File/Edit/View/Window/Help 等系统菜单；Windows/Linux 默认收起菜单栏，并遵循系统 Alt 唤出约定。菜单动作路由到当前聚焦的 Corvid 窗口及用户控制的活动 Room/Tab；Agent 所有、等待接管或存在未决执行风险时，页面导航、标签修改、查找/打印和缩放操作保持禁用。菜单语言跟随应用级 `zh-CN` / `en` 偏好。此合同由 [Issue #162](https://github.com/heyallencao/corvid/issues/162) 跟踪，真实运行态与平台覆盖仍待验收。
- **主画布：** 当前 Browser Page，由 Chromium `WebContentsView` 呈现。它的原生 bounds 顶边由各个壳层窗口的 `#browser-shell` 实测高度驱动；CSS 高度变化时经窗口专属 IPC 同步给主进程，避免固定坐标覆盖标签、书签栏或状态条。资料库面板和站点工具菜单共用该高度及间距变量，网页视图与壳层覆盖层保持在同一 chrome 边界之后。
- **新标签起始页：** 用户新建的空白标签仍保持 `about:blank` 页面合同，由 Corvid 壳层显示本地起始体验：地址/搜索输入、当前浏览身份的常用书签、全部书签、历史和 Corvid Agent 入口。起始页收起重复的浏览器书签栏；导航使用现有地址栏提交路径，继续遵守用户配置的搜索模板和 URL 校验。起始页不创建网络页面，不进入 Agent 页面上下文；显示期间隐藏对应窗口中的 Chromium 页面视图，离开空白标签后按原布局恢复。视觉方向参考已核验的 EGO 日常浏览模式；Kaze 新标签行为没有足够运行态证据，本设计不对其作推断。
- **Corvid Agent 对话工作区：** 右侧并行面板采用持续聊天布局，空态引导、单线程消息流直接排在面板底色上，运行/失败/停止状态以行内状态行与警示条就近显示，历史按对话收起，可选中后续聊。输入区由徽章行（页面来源胶囊 + 模型/连接胶囊，连接与模型管理收进模型弹出面板）和内嵌发送按钮的无边框输入组成。页面上下文采用托管模型（2026-11-07，[Issue #407](https://github.com/heyallencao/corvid/issues/407) 产品决策）：把空间交给 Agent 即授权其读取该空间内已绑定页面的上下文，界面只常驻展示页面来源，不再有逐条预览同意流程；Agent 正在运行时照常发送，消息自动排队并在本轮完成后按序自动派发。接管/失败/停止未确认等关键状态保留完整文字警示条，不以图标隐藏语义。conversation 与 Agent Room/task/transcript 保持清晰对应。交互密度参考 REA 可见的 Kaze Agent 面板和模型/输入相对位置，Corvid 保留自己的视觉语言、EGO 式日常浏览主线及托管授权合同。当前切片由 [Issue #56](https://github.com/heyallencao/corvid/issues/56) 跟踪；此前 2026-11-06 的输入区分层与任务卡布局见 [#377](https://github.com/heyallencao/corvid/issues/377)、[#378](https://github.com/heyallencao/corvid/issues/378)、[#381](https://github.com/heyallencao/corvid/issues/381) 与[工作台布局重构视觉检查](../qa/issue-377-workbench-layout-refactor.md)。
- **通用列表与设置：** 复用统一的标题、搜索、空态、条目、错误和确认组件。

## 日常工具面板与设置中心的完成度

2026-11-03 的隔离 UI 复核发现，书签、历史、下载和 Agent 工作区虽然入口可达，但空态仍较接近通用卡片：右侧固定面板重复品牌眉题、标题和搜索框，正文只有一句状态文字，缺少按当前任务选择的下一步；设置则把语言、搜索、导入、扩展和外部 Agent 授权放入同一对话框，主题和下载等常用浏览器偏好不集中。仅有统一 CSS token 不足以形成成熟产品的品牌完成度。

后续打磨应把品牌名控制在必要的位置，以清楚的区域标题、语义分组、稳定的内容密度和有用的空态区分浏览器导航、资料库与 Agent 工作区。空态只提供当前任务真正需要的行动，不为装饰而加图或动效。设置中心需要明确“应用级 / 浏览身份级 / 当前站点级”配置范围，并把主题、启动、新标签、搜索、下载、权限/数据、扩展和 Agent/模型入口组织到可扩展分组；首发中英文与凭据保护分别遵循 D23、Issue #130 与 Issue #110，不能引入第二份状态。

参考只用于说明层级：Kobra 的组件工作台以导航、预览、上下文说明分区；Aceternity 的分组侧栏展示主导航与独立组的层级表达。二者是组件/文档站结构灵感，不能决定浏览器需要哪些设置，也不构成采用其配色、三栏比例或装饰动效的要求。该方向分别由 [Issue #16](https://github.com/heyallencao/corvid/issues/16) 的界面打磨与 [Issue #165](https://github.com/heyallencao/corvid/issues/165) 的设置中心交付。
