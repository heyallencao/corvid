# Issue #244：GitHub 截图证据治理

## 目标与范围

让 UI/UE Issue 与 PR 中的图片长期可访问、来源安全且便于复核。截图只能补充复现、影响和验收说明，不能替代这些文字，也不能单独证明未覆盖的交互或稳定性。

## 验收合同

1. 盘点开放 Issue/PR 中 Markdown/HTML 图片引用及截图说明中的路径；区分本机路径、相对路径、其他分支链接和稳定链接。
2. 需要保留的图片使用 GitHub 附件或合并到 `main` 的 `docs/qa/screenshots/` 资产。PR 评审期可以链接该 PR 自身分支中的图片，合并后必须更新正文并确认 `main` URL。
3. 分享前检查网页主体、账号、凭据和私人浏览数据；无法确认隔离与脱敏时不上传。
4. 保留复现条件、用户影响、预期结果及可验收条件；明确截图的状态、窗口尺寸、时间、来源和限制。
5. 中文 PR 模板提供流程要求，自动检查拒绝本机/相对图片路径、指向其他分支的图片，且在合并事件上拒绝仍依赖 PR 分支的图片。
6. 分批处理已有内容；受其他活动 PR 影响或缺少安全来源图时，不替换、重拍或代其他负责人改写。

## 当前进度

- PR #250 已合并中文 PR 模板；PR #247 的两张 QA 截图 URL 已改为 `main` 固定路径，Contents API 证明资产存在，但 GitHub 登录态下的页面实际渲染仍待复核。
- 本执行切片加入自动链接检查。它只检查 PR 描述，不读取 Issue 正文，也不验证图片内容或脱敏质量。
- 2026-11-04 初始盘点记录：8 个开放 PR 含非稳定分支图片链接；11 个其他开放 Issue 正文含本机临时截图路径。逐条清理和页面渲染复核仍未完成；每轮应重新读取 GitHub 状态，不将该数字当作当前值。

## 操作规则

- 对 PR 图片：评审期使用当前 PR 的分支链接；合并后改用 `https://github.com/<owner>/<repo>/blob/main/docs/qa/screenshots/...`，然后通过已登录 GitHub 页面确认实际渲染。
- 对 Issue 图片：使用 GitHub 附件，或仓库中已合并且稳定可达的 QA 图片；不要引用作者本机路径或某个可删除分支。
- 检查器是链接卫生门槛，不会认可截图安全性、布局正确性、行为完整性或 REA 证据质量。
- 若目标仓库私有且浏览器未登录，应记录“页面渲染未验证”；API 返回文件存在不能替代页面检查。
