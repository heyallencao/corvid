# 端到端测试索引

本索引覆盖 `tests/` 下 61 项入口，其中 `tests/pi-real-model-smoke.cjs` 为需显式运行的真实模型验收，不属于 `npm test`。当前 `npm test` 配置包含 1 条 `node --test` 命令（7 个文件、27 个 `node:test` 用例）和 55 条独立脚本命令，共 82 项自动化检查；原生菜单模块合同见 `tests/application-menu.test.mjs`。索引中的序号按 `package.json` 的 test 脚本顺序排列。除 `tests/recovery-e2e.cjs`（预期启动失败）、`tests/agent-runtime-contract-e2e.cjs`、`tests/agent-task-continuation-contract.cjs`、`tests/agent-message-queue-contract.cjs`、`tests/profile-deletion-services.cjs`（隔离数据目录的模块合同测试）和 `tests/electron-startup.e2e.mjs`（启动/清理诊断替身）外，每项都会启动真实 Electron；`tests/sdk-e2e.cjs` 先启动桌面，再运行 `sdk/e2e.js`。结果记录见 [验证记录](../reviews/verification-log.md)，各工作块的验收合同见 [执行任务板](../execution/feature-board.md)。

## 共同前提与限制

- 环境：本机 macOS、Electron 45.2.1、Node.js v24.14.1；Issue #113 多窗口同步修正后，2026-11-03 连续两轮全量串行回归均退出码 0，每轮 45 条独立脚本命令 + 3 个 `node:test` 用例，共 48 项。
- 全量回归：历史上的 Electron 启动挂起由 [Issue #87](https://github.com/heyallencao/corvid/issues/87) 跟踪；地址栏草稿在延迟 `shell-state` 刷新后被覆盖的问题由 [Issue #101](https://github.com/heyallencao/corvid/issues/101) 跟踪并在当前主线修复。Issue #113 后的两轮历史基线均通过；Electron 启动与清理诊断用例现已纳入全量 `npm test`，2026-11-03 在 Issue #141 macOS 验收中包含该用例的 70 项回归全部通过。Issue #87 跟踪的早期偶发挂起根因仍未确定，单次全量通过不代表根因已定位，细节见[验证记录](../reviews/verification-log.md)。
- 隔离：每项自建临时数据目录（`CORVID_DATA_DIR`），使用 `CORVID_PORT=0`、`CORVID_TEST_MODE=1`，下载相关使用 `CORVID_TEST_DOWNLOAD_DIR`；页面来自本地 HTTP 夹具（`127.0.0.1` 随机端口，部分用 `localhost` 制造跨来源）；不读写真实用户数据。
- 测试替身：权限确认、执行风险复核、Room 认领、关闭 Room、站点数据清理、站点权限撤销、beforeunload/标签关闭确认等系统对话框由 `dialog.showMessageBox` / `showMessageBoxSync` 替换；普通下载用测试目录绕开 `showSaveDialogSync`；下载"打开文件/在文件夹中显示"在测试中替换 `shell.openPath` / `shell.showItemInFolder`，只验证应用转发路径与错误呈现。原生对话框与真实系统应用交互本身未验证。
- 未覆盖：真实网站、真实用户数据、Windows、打包与分发、跨源 iframe 内容、closed Shadow DOM、`networkidle`、同步 renderer 卡死、断电/写入中断恢复、能读取管理员 `control.json` 的恶意同用户进程之间的 OS 级隔离；SIGKILL 恢复仅覆盖已提交状态后的 Room/标签与 Agent task 恢复。
- 每项结束时清理自己创建的 Electron 进程、HTTP 服务与临时目录。

- 55 个独立脚本：例如 `node tests/rpc-e2e.cjs`、`node tests/user-control-e2e.cjs`、`node tests/sdk-e2e.cjs`、`node tests/contract-e2e.cjs`、`node tests/snapshot-e2e.cjs`、`node tests/agent-rooms-panel-e2e.cjs`、`node tests/agent-access-e2e.cjs`、`node tests/agent-access-ui-e2e.cjs`、`node tests/mcp-e2e.cjs`、`node tests/pi-runtime-e2e.cjs`、`node tests/localization-e2e.cjs`，其余按 `package.json` 中顺序运行。
- `tests/sdk-e2e.cjs` 会自行启动隔离桌面并运行 `sdk/e2e.js`；如已单独启动桌面，也可在相同 `CORVID_DATA_DIR` 下直接运行 `node sdk/e2e.js`。
- 沙箱/CI 环境需清理 `ELECTRON_RUN_AS_NODE` 并允许 Chromium 建立沙箱，否则真实 Electron 可能无法启动。

## 维护约定

- 新增或修改测试时，必须同步更新本索引、[验证记录](../reviews/verification-log.md) 和 [执行任务板](../execution/feature-board.md) 中对应工作块的证据。
- "通过"只记录当次真实运行；不得用 API 级结果代替 UI 结果，也不得用本地夹具结果替代真实网站结论。
- 系统对话框替身、非 `isTrusted` 合成事件和轮询实现必须在"关键限制"列写明。
- 人眼布局检查不属于自动化项，记录在 [桌面 UI 视觉检查记录](ui-visual-check.md)，并在相关验收合同的证据列引用。
